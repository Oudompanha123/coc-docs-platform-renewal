# Use Case UC-002: Create a new page in a section

> **REQ-ID**: UC-002
> **Version**: 1.0
> **Preceding Document**: [REQUIREMENTS-SPEC.md](../REQUIREMENTS-SPEC.md)

---

## 1. Scenario Overview

| Item | Description |
|------|------|
| **Primary User** | `admin` (non-technical) |
| **Preconditions** | Signed in as `admin`; the target section exists |
| **Trigger** | New documentation is needed for an existing product area |
| **Outcome (Success)** | A new page is live and appears in the reader navigation |
| **Outcome (Failure)** | Creation refused with a clear reason; no partial page left behind |
| **Related FR** | FR-CONT-006, 007, 008, 009, 010, 014 · FR-NAV-004, 005 · FR-I18N-001, 006 |
| **Related NFR** | NFR-EXT-01, NFR-USE-02, NFR-SCALE-01 |
| **Related BR** | BR-001, BR-002, BR-003, BR-006, BR-007 |

> **What this replaces**: today, adding a page means editing `lib/i18n.ts`, `Sidebar.tsx`, and all three `content/{lang}/<set>.tsx` files, then running a build to check the page count (`CLAUDE.md:24-29`). Four code locations, three languages, one deploy.

## 2. Main Flow

| Step | Actor | Action | System Response |
|------|------|------|------------|
| 1 | `admin` | Chooses a section, clicks **New page** | Blank page form opens |
| 2 | `admin` | Enters title and navigation label | Slug suggested from the title, editable (**FR-CONT-008**) |
| 3 | System | — | Slug uniqueness checked within the section (**BR-001**) |
| 4 | `admin` | Adds body content from the block menu | Blocks appended in order (**FR-CONT-009**) |
| 5 | `admin` | Sets the page position in the section | Order stored as a single explicit value (**FR-NAV-004**) |
| 6 | `admin` | Saves draft, previews, publishes | Page live; navigation rebuilt from the database (**FR-NAV-005**) |
| 7 | System | — | Warns that km and ko versions do not yet exist (**FR-I18N-006**) |

## 3. Alternative Flow

### 3.1 A-1: Duplicate an existing page
- Branches at Step 1; the admin duplicates a similar page as a starting point (**FR-CONT-014**)
- Outcome: new page pre-filled with the source blocks; the slug must still be unique

### 3.2 A-2: Insert an interactive component (Tier B)
- Branches at Step 4
- Action: the admin inserts an **embed block** and picks a registered component by name (**FR-CONT-010**)
- Outcome: `HarnessDemo` / `OwnerTree` render for readers. The component stays in code — the admin references it, never edits it

### 3.3 A-3: Create all three languages at once
- Branches at Step 6; the admin creates km and ko versions immediately
- Outcome: coverage stays at 100% (**NFR-I18N-01**); no missing-translation warning raised

## 4. Exception Flow

### 4.1 E-1: Duplicate slug
- Occurs at Step 3. Action: creation blocked, an available alternative suggested. Outcome: no collision with an existing page or its redirects.

### 4.2 E-2: Reserved or malformed slug
- Occurs at Step 3. Action: rejected with a plain-language explanation. Outcome: routing conflicts prevented.

### 4.3 E-3: Abandoned before publish
- Action: the page remains a draft, invisible to readers, listed as Draft in the admin. Outcome: no half-created page appears in navigation.

### 4.4 E-4: Page later deleted (**FR-CONT-007**)
- Action: soft delete; internal references to it are flagged in the admin console.
- Outcome: readers get the styled 404 (**FR-READ-004**); no dangling link goes unreported.
