# Use Case UC-007: Find and fix a stale translation

> **REQ-ID**: UC-007
> **Version**: 1.0
> **Preceding Document**: [REQUIREMENTS-SPEC.md](../REQUIREMENTS-SPEC.md)

> **This use case exists to replace a safety property the migration destroys.** Today `panels: Record<Slug, ReactNode>` makes TypeScript **fail the build** if any language is missing any page, which is why coverage is 100%. A database cannot enforce that. UC-007 is the compensating control.

---

## 1. Scenario Overview

| Item | Description |
|------|------|
| **Primary User** | `admin` (non-technical), often a translator |
| **Preconditions** | Signed in as `admin`; at least one page has been edited in `en` since its km or ko version was published |
| **Trigger** | Routine check, or a dashboard prompt |
| **Outcome (Success)** | The translation matches the current English, and the stale flag clears |
| **Outcome (Failure)** | Nothing silently breaks — the stale translation stays published and readable |
| **Related FR** | FR-I18N-002, 003, 004, 005 · FR-CONT-003, 004, 005 |
| **Related NFR** | NFR-I18N-01, NFR-USE-02, NFR-OPS-AUDIT |
| **Related BR** | BR-011, BR-012, BR-013, BR-014 |

> **Definitions fixed by AMB-002** — the two are deliberately different measures:
> - **Coverage** = a *published version exists* in all three locales. Target 100% (**NFR-I18N-01**).
> - **Staleness** = a published translation whose `en` source changed after it. **Staleness is not a coverage breach.**
>
> Without this distinction BR-011 would be violated by the first edit anyone made, which is why it was contradictory before (C-02).

## 2. Main Flow

| Step | Actor | Action | System Response |
|------|------|------|------------|
| 1 | `admin` | Opens **Translation status** | Per language: pages **missing** and pages **stale** (**FR-I18N-003**) |
| 2 | `admin` | Picks a stale page in km | Editor opens the km version |
| 3 | System | — | Shows what changed in `en` since this translation was published |
| 4 | `admin` | Updates the km text | Only the km version is affected (**FR-I18N-005**) |
| 5 | `admin` | Previews and publishes | km republished; stale flag cleared |
| 6 | System | — | Audit entry recorded; ko remains stale and is untouched |

## 3. Alternative Flow

### 3.1 A-1: Translation missing entirely
- Branches at Step 1 — the page has no km version at all
- Action: the admin creates it
- Outcome: **coverage** rises toward 100%. This is the case that actually breaches NFR-I18N-01

### 3.2 A-2: Accept a stale translation as still correct
- Action: the admin marks the translation reviewed without editing it (e.g. the `en` change was a typo fix that does not affect km)
- Outcome: stale flag clears without a content change; the decision is audited

### 3.3 A-3: Bulk view before a release
- Action: the admin reviews every stale page at once
- Outcome: a work list rather than a per-page hunt

## 4. Exception Flow

### 4.1 E-1: English edited again mid-translation
- Occurs between Steps 2 and 5
- Action: on publish, the admin is told the source moved again; the page stays stale
- Outcome: **no false "up to date" signal** — the flag reflects reality, not effort

### 4.2 E-2: Publishing English creates staleness (**FR-I18N-002**)
- Action: km and ko are marked stale automatically
- Outcome: **both remain published and readable** (**FR-I18N-004**). Staleness never takes a page offline

### 4.3 E-3: Non-reference language edited
- Action: an admin edits km directly
- Outcome: **no staleness propagates.** Staleness flows only from `en`, the reference language

## 5. Non-Functional Requirements Mapping

| NFR-ID | Application |
|--------|------|
| **NFR-I18N-01** | Step 1 is the measurement instrument for the 100% coverage requirement |
| NFR-USE-02 | A translator needs no code, no file paths, no build |
| NFR-OPS-AUDIT | Steps 5–6, including A-2 "reviewed without change" decisions |

## 6. Test Scenarios

| Test ID | Case | Input | Expected Result |
|-----------|--------|------|---------|
| TC-007-01 | Happy path | Fix a stale km page and publish | Flag clears; ko unaffected |
| TC-007-02 | **Staleness created** | Publish an `en` edit | km and ko marked stale, both still readable |
| TC-007-03 | **Stale is readable** | Reader opens a stale km page | Renders normally, no reader-facing warning |
| TC-007-04 | Missing translation | Page with no km version | Listed as missing, not stale; counts against coverage |
| TC-007-05 | Source moved again | `en` edited mid-translation | Publish warns; page stays stale |
| TC-007-06 | Review without change | Mark reviewed, no edit | Flag clears; decision audited |
| TC-007-07 | No reverse propagation | Edit km directly | `en` and ko unaffected |
| TC-007-08 | **Coverage measurement** | Delete a km version | Coverage drops below 100%; NFR-I18N-01 fails |
